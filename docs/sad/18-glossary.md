# 5. Appendices

## 5.1 Glossary

The following terms and abbreviations are used in the Software Architecture and Design Specification for the IT Infrastructure & Asset Management System.

| Term | Definition |
|---|---|
| ITAM | IT Asset Management; the process of tracking and managing an organization's IT assets throughout their lifecycle. |
| SAD | Software Architecture and Design Specification; describes the system architecture, components, interfaces, and design decisions. |
| SRS | Software Requirements Specification; documents the functional and non-functional requirements of the system. |
| STP | Software Test Plan; defines the testing approach, test environment, test schedule, and planned verification activities. |
| RTM | Requirements Traceability Matrix; maps requirements to corresponding test cases and verification activities. |
| UML | Unified Modeling Language; a standard notation used to represent system structure and behaviour through diagrams. |
| UI | User Interface; the part of the system through which users interact with the application. |
| UX | User Experience; the overall experience users have while interacting with the system. |
| API | Application Programming Interface; a defined interface through which software components communicate. |
| HTTP | Hypertext Transfer Protocol; a protocol used for communication between clients and servers. |
| HTTPS | Hypertext Transfer Protocol Secure; HTTP communication protected using TLS. |
| JSON | JavaScript Object Notation; a structured data format commonly used for API requests and responses. |
| DBMS | Database Management System; software used to create, manage, and access databases. |
| Database | An organized collection of information stored for retrieval and management by the application. |
| RBAC | Role-Based Access Control; an approach that assigns permissions based on user roles. |
| Authentication | The process of verifying a user's identity. |
| Authorization | The process of determining which operations a user is permitted to perform. |
| Asset | An item of IT equipment or software that an organization tracks and manages. |
| Asset Allocation | The assignment of an asset to a user, department, or other authorized recipient. |
| Maintenance Record | Information documenting maintenance performed or planned for an asset. |
| Software License | An authorization or agreement governing the permitted use of software. |
| Warranty | A guarantee covering specified repairs or replacements under defined conditions and dates. |
| Component | A modular part of a system that has a defined responsibility and interacts with other parts through interfaces. |
| Layered Architecture | An architectural pattern that separates a system into logical layers with distinct responsibilities. |
| Data Integrity | The accuracy, consistency, and reliability of stored information. |
| TLS | Transport Layer Security; a protocol used to protect data transmitted over a network. |
| Validation | The process of checking whether submitted information meets specified rules and constraints. |
| Logging | The recording of relevant application events, errors, or activities for analysis and troubleshooting. |
| Monitoring | The observation of system operation to identify errors, performance issues, or availability problems. |
