# 7. Test Schedule

## 7.1 Testing Timeline

Testing activities will be carried out in coordination with application development and documentation.

| Activity | Planned Timeline | Description |
|---|---|---|
| Test planning | During planning | Define testing scope, strategy, and responsibilities. |
| Test case preparation | After requirements are identified | Prepare test cases based on the SRS. |
| Unit testing | During implementation | Test individual functions and components. |
| Integration testing | After component integration | Verify interactions between modules. |
| System testing | After major features are implemented | Test the complete application against requirements. |
| Security testing | During system testing | Check access control, input validation, and data protection. |
| Defect fixing and retesting | Throughout testing | Correct defects and verify fixes. |
| Final testing and reporting | Before submission | Record results and prepare the final test report. |

## 7.2 Schedule Dependencies

The schedule depends on the availability of implemented features, approved requirements, test data, and a working application environment.

If development or integration is delayed, the testing schedule will be adjusted accordingly.

## 7.3 Progress Tracking

The team will track testing progress using the test case records in the repository. Each test case will be marked as Not Run, Pass, or Fail after execution. Defects and unresolved issues will be documented and reviewed before final submission.
